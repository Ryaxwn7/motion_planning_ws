Topic
Fix host UI shape publish path so a shape update also triggers FM2 gather navigation goals.
Decisions
- Root cause was UI semantics: `Apply Shape` only wrote `/shape_task_supervisor/shape_type` and `shape_scale`; it did not publish `/gather_signal=2`.
- This allowed `shape_task_supervisor` to republish a `ShapeTask` from the last latched `/gather_center`, so robots could receive the new shape while `fm2_gather` never recomputed or dispatched move_base goals.
- Changed the UI button label from `Apply Shape` to `Publish Shape` and made it apply shape params then request gather.
- Made UI gather publication wait briefly for a subscriber and repeat the `std_msgs/UInt8(data=2)` signal three times at 5 Hz to reduce startup/reconnect message loss.
