Time: 2026-04-22T04:41:56Z
Topic: Consolidate host and robot startup parameters into central YAML files and auto-materialize node-specific configs at launch time.

Decisions
- Switched `start_host.sh` default config from `config/host_start.conf` to `config/host_param.yaml`, while keeping legacy `.conf` support.
- Switched `start_robot.sh` default config from `config/robot_start.conf` to `config/robot_param.yaml`, while keeping legacy `.conf` support.
- Added `startup_param_loader.py` to read the central YAML, generate temporary node-level YAML files, and emit shell assignments consumed by the startup scripts.
- Centralized host-side `fm2_gather` parameters in `config/host_param.yaml` and robot-side `shape_assembly` / `graph_planner` / `MyPlanner` / costmap parameters in `config/robot_param.yaml`.
- Added `graph_planner_config` as a first-class launch arg in the real-robot `move_base` chain so robot-side global planner parameters can be injected from `robot_param.yaml`.
- Updated `host_control_ui.py` to read the new YAML-based host config path through the same materialization path as `start_host.sh`.
